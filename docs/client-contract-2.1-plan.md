# 前后端契约 2.1 实施计划

批准基线：`cbc93c7`，2026-09-18。接口仍为 `/api/v2`，契约版本为 `2.1`，玩法规则为 `2.0`。不保留 rc.1 接口兼容层，不修改旧 3000 网页部署，不实现前端或服务器重启恢复对局。

## 固定决策

- Room 是持续房间，RoomMember 是账号的当前房间身份，Game 是一次对局，Participant 是该局不可替换的玩家记录。每次开始产生新 gameId、playerId、随机座位及角色。房间码、roomId、规则配置跨局保留。
- 一个账号同时最多处于一个房间。原对局玩家离开后仍可恢复本人，不能转为该局观众。大厅新进入者有位则正式、满员则公开观众；游戏和复盘中的新人为公开观众。观众只在大厅显式申请转正式，失败保留原身份。
- 断线保留正式成员及准备状态。正常断线有 15 秒 reconnecting；心跳 interval=10s、timeout=20s，ping timeout 不再叠加宽限期。仅有效控制会话连接计入玩家在线。主动离开或控制会话注销立即离开；其他设备注销不影响控制设备。密码变更/会话过期只撤销连接、标记离线。
- 房主各阶段可手动转给在线正式成员；自动转给加入最早的在线正式成员。死亡不影响房主资格，无人可选时为空。返回者不夺回已有房主。开局条件仍为人数齐、全部准备、房主发起，不额外要求全员在线。
- 正式成员为零启动 5 分钟倒计时，正式加入或原玩家恢复取消；观众不延长。到期解散，进行中对局记 aborted，保留审计。移除旧的无人连接 2 小时/终局 24 小时回收策略。
- 房主可以单方结束复盘回大厅；保留当前成员，所有正式成员取消准备。第二屏仅开局后签发，5 分钟一次兑换，每玩家最多一屏，绑定 gameId。结束复盘撤销邀请和私有授权，观众降为公开，下一局重新授权。
- 账号名作为房间与对局显示名，不再单独填写昵称。保持账号、密码、有效会话，新增迁移先在数据库副本验证。规则只有默认 13 人正式板；其他角色组合均实验，人数须与角色总数一致。
- snapshot 总是包含 viewer、room、public、private、capabilities、tasks、windows、submissionState、serverTime、viewVersion。lobby 的 gameId 为 null。viewVersion 按账号+房间计算，只随其授权内容变化。Socket 使用 roomId 握手、跨局保持订阅；gameId 变化清空客户端局内缓存。
- 所有房间写操作带 requestId；局内写操作带 gameId。命令回执可查 not_seen/pending/accepted/rejected，查询不执行命令。聊天使用 clientMessageId 去重，返回与推送同一个 messageId，无全局隐私序号。
- 注册邀请码预检不消费，注册事务再次校验。注册响应丢失通过登录恢复。bootstrap 提供真实约束，catalog 提供角色、预设及完整规则章节；规则搜索在客户端完成。
- 头像接收已裁剪的正方形静态 JPEG/PNG/WebP，2 MiB、边长至多 4096；拒绝 SVG、动画、伪装格式。Sharp 限像素和并发，重编码 256×256 WebP 去元数据；写完才更新引用。默认头像 null，认证下载，7 天后回收无引用文件。

## 小步交付与验收

每行独立短分支；有多个行为继续拆提交。主代理实现，Luna 只修改指定测试，冻结被测源码；记录 SHA、差异摘要、只读挂载、命令、结果与边界，再本地合入 `backend/client-contract-2.1`。

| 01 | 契约定义、计划、隔离环境 | DTO 类型、源码挂载、cookie 隔离 |
| 02 | 持续房间与单局运行时、审计关联 | 稳定 roomId/新 gameId、规则冻结、审计 |
| 03 | 进入、恢复、单房间约束、转正式 | 并发进入/失败原子性/本人恢复 |

| 05 | 房主转移、主动解散 | 各阶段在线成员、无房主/返回 |
| 06 | 空房 5 分钟/中止 | 离线成员保留、取消回收、中止审计 |

| 11 | 头像处理与回收 | 格式/大小/像素/动画/失败不替换 |
| 12 | OpenAPI、完整例子、联调指引 | DTO/mock 对齐、代理/Cookie/Socket 示例 |
| 13 | 候选发布与回滚 | 一次完整单元/API门禁、迁移副本、5分钟容量 |

## 环境及完成标准

开发实例 127.0.0.1:3003，独立 data-contract-2.1，独立 cookie `td_account_contract_21`。旧 3001 候选在最后切换前保留。所有构建、运行、测试在 Docker 中；依赖未变不重建依赖镜像。Sharp 引入时单独更新锁文件/依赖层。增量测试默认只跑指定文件与必要类型检查。

候选发布构建一次全量单元/API门禁，不跑旧 UI E2E。再次执行 2 核/4 GB、100账号、50持续连接（26玩家/24观众）的5分钟文字容量：API P95 <300ms，事件循环 P99 <100ms，进程 RSS <1GB，无异常5xx、重复执行、权限泄漏。头像/密码/真实语音负载分开报告，不声称已验证真实语音容量。

最终在无进行中对局时备份新版账号库与审计库，再切换 3001、恢复标准 cookie 名。保留旧候选镜像与对应备份；旧程序拒绝新版 schema 时必须镜像+数据库配套回滚。候选标签 `v2.1.0-rc.1` 固定源码 SHA、镜像摘要和迁移版本。无自动推送、远端合并、公网发布。
